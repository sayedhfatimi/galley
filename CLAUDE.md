# galley

Markdown in, a typeset PDF **and** the LaTeX source that produced it out — compiled by a real TeX engine running entirely in the browser. No account, no server, no uploads.

## Package manager

Use **`bun`** exclusively. Never run `npm install`, `pnpm`, or `yarn` here.

## Quality checks

Run all four before every commit: `bun run check` (Biome), `bun run typecheck`, `bun run test`, `bun run build`.

## Architecture

Static SPA, no backend. `src/core/` is **pure** — no DOM, no React — so it runs identically in Node under Vitest, on the main thread, and inside the compile worker. UI lives in `src/ui/`, the TeX engines are owned solely by `src/workers/compile.worker.ts`, and the bundled TeX Live tree sits in `public/texlive/`.

**`src/core/fonts.ts` is the single source of truth for typefaces.** The preamble, `scripts/build-texlive-bundle.ts` and `preamble.test.ts` all read from it; never restate a face filename anywhere else. Adding a typeface means editing that registry and re-running the bundle script, which needs a local TeX Live.

**`src/core/images.ts` owns the one sanitised name per figure.** The Markdown, the IndexedDB key, the engine's filesystem path and the `\includegraphics` argument must all be the same string, and `\includegraphics` tokenises its argument. Sanitise at ingest, never at the point of use.

**Keep the engine behind the worker interface.** Nothing outside `compile.worker.ts` may know which TeX engine is in use — v1 ships SwiftLaTeX's 2022 XeTeX + dvipdfm, and swapping it for a current engine is planned work, not a rewrite.

## Bundled artefacts

`public/texlive/` is committed, so neither CI nor a contributor needs a TeX installation. Two scripts produce it and both are maintainer-only — see `scripts/README.md`. `swiftlatexxetex.fmt` cannot be regenerated by the bundle script and is preserved across its rebuild; a format file is engine-specific and must be built by the engine that reads it.
